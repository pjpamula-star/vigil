# Research notes — 2026-10-16

What we learned before designing Vigil. All measurements below were taken on this machine: a Windows laptop running Windows 11 Home 26200 with Claude Code 2.1.301, signed in with a claude.ai account.

## 1. Why the PC went to sleep mid-build

- The current power plan sleeps after **5 min idle on AC** and **3 min idle on battery**.
- **Closing the lid** is set to Sleep.
- The laptop uses **Modern Standby (S0 Low Power Idle)**, not classic S3 sleep. After the screen turns off:
  1. **Screen-off.** The display timeout only turns off the screen, and apps keep running.
  2. **NoCS phase.** Once the *sleep* timeout passes, Windows enters standby. Power requests (`PowerSetRequest`) can hold this phase **indefinitely on AC, but only about 5 minutes on battery (DC)**.
  3. **DAM (Desktop Activity Moderator).** This phase suspends desktop apps, including the terminal and `claude`.
- **User-initiated sleep** (lid set to Sleep, power button, Start > Sleep) ignores and terminates power requests.
- `SetThreadExecutionState` alone is not enough on Modern Standby laptops. See PowerToys Awake issue #48965 and Claude Code issue #71875.

**Conclusion:** keeping the PC awake reliably, on battery and with the lid closed, needs *both* of these during a session:

1. Power-setting overrides, applied with `powercfg` (no admin required) to the active scheme:
   - `STANDBYIDLE` AC/DC set to 0 (never idle-sleep)
   - `LIDACTION` AC/DC set to 0 (closing the lid does nothing)
2. A power request held for the whole session: `PowerCreateRequest` plus `PowerSetRequest` with `SystemRequired` and `ExecutionRequired`.

It also needs a **journal, written before any change**, recording the original values. They are restored when the session ends, at app start if the app crashed, and by a non-admin scheduled task as a backstop.

## 2. Knowing when Claude is working: hooks

Claude Code hooks fire on these events:

| Event | Useful fields | What Vigil uses it for |
|---|---|---|
| SessionStart | `source` | Session appears |
| UserPromptSubmit | `prompt` | Session becomes **working** |
| PostToolUse | tool name, input | Files changed and commands run (for the summary) |
| Notification | `permission_prompt`, `idle_prompt`, `agent_needs_input`, … | Session becomes **needs you** |
| Stop | `last_assistant_message`, `background_tasks` | Session becomes **done** (unless background tasks remain) |
| StopFailure | `error` (rate_limit, overloaded, auth…) | Session becomes **failed** |
| SubagentStart/Stop | | Session counts as working while subagents run |
| SessionEnd | `reason` | Session closed (1.5 s default timeout) |

All events also carry `session_id`, `transcript_path`, `cwd`, `permission_mode` and `hook_event_name`.

Hooks can be **HTTP** (a JSON POST to a local URL; a failed connection doesn't block Claude) or **command** hooks (exec form, `async: true`). Vigil will install HTTP hooks that point at its local listener, so Claude never waits on Vigil and nothing breaks when Vigil isn't running.

Transcripts are JSONL files at `transcript_path`. The summary can read the final assistant message and the list of edits from them.

## 3. Phone access: Claude Code Remote Control

This is the built-in, official way to drive **terminal** sessions from a phone. It doesn't need a custom server, tunnels or open ports.

- It connects the **Claude mobile app** (Code tab) or claude.ai/code to a `claude` process running on this PC. Claude keeps running locally, and the phone is a window into that session.
- **Requirements:** a Pro, Max, Team or Enterprise plan with a claude.ai login (API keys are not supported). This machine qualifies (`authMethod: claude.ai`).
- **Ways to turn it on:**
  - `/remote-control` (or `/rc`) inside a running session, which carries over the history so far.
  - `claude --remote-control` (or `--rc`) to start a new interactive session that is also remote.
  - `claude remote-control` (**server mode**), which lets you start *new* sessions from the phone. Flags: `--spawn same-dir|worktree|session`, `--capacity N` and `--permission-mode`. Press space to show a QR code.
  - **Auto-connect every session:** `/config` → *Enable Remote Control for all sessions*, or `"remoteControlAtStartup": true` in `~/.claude/settings.json`.
- **On the phone:** open Claude app → **Code**. Each session appears with a computer icon and a green dot when online. Tap one to read the conversation live, send prompts, attach photos or files, answer permission prompts, and change the model or effort.
- **Push notifications:** `/config` → *Push when Claude decides* and *Push when actions required*. Claude Code already skips pushes while you're typing in the terminal. Set `CLAUDE_CLIENT_PRESENCE_FILE` to a marker path to also skip them whenever you're at the PC. Vigil can create that file on unlock and delete it on lock.
- **Limitations:**
  - The PC must stay awake and `claude` must keep running. Vigil exists to solve this.
  - One remote session per interactive process; server mode allows many.
  - Local-only commands like `/plugin` and `/resume` don't work from the phone.
  - A line that starts with `!` sent from the phone is treated as a message, not a shell command.
  - Server mode exits after about 10 minutes without network.
- **Security:** outbound HTTPS only, with no inbound ports. The transcript is stored on Anthropic's servers while connected. Optional "Trusted Devices" adds biometric re-checks.
- `/mobile` shows a QR code for downloading the app.

**Common misconception:** the regular chat view in the Claude app does *not* show terminal sessions. They appear only in the **Code** section, and only after Remote Control is enabled for them.

## 4. Heat and battery protection without admin

Measured on this machine without elevation:

| Source | Result |
|---|---|
| `\Thermal Zone Information(*)\Temperature` | Returns **0**, so it can't be used |
| `MSAcpi_ThermalZoneTemperature` (WMI) | **Access denied** |
| `\Thermal Zone Information(*)\% Passive Limit` | Readable; 100 = no throttling, lower = firmware throttling for heat |
| `\Thermal Zone Information(*)\Throttle Reasons` | Readable; nonzero = throttling |
| `\Processor Information(_Total)\% Performance Limit` | Readable; drops below 100 when limited |
| Battery % / AC status | Readable via `GetSystemPowerStatus` |

**Plan:** use the throttling signals as the heat alarm, because they come from the firmware's own safety logic. Real temperature in °C would need an optional elevated helper. Kernel drivers like WinRing0 get flagged by Defender, so they're avoided.

## 5. UX research takeaways

- **Insomnia (macOS):**
  - Status comes first in the menu, and copy is plain and specific.
  - Ending a session is a hold-to-end gesture (a 0.6 s ring), which prevents accidental clicks.
  - Typing a duration like `2h` takes one keystroke.
  - It never promises success it can't verify.
  - It journals settings before changing them.
- **Amphetamine:** the icon dims when inactive, and *triggers* (stay awake while an app or process runs) are popular.
- **Catch-up digests** (Slack "while you were away", GitHub notifications) work best with:
  - a bounded window ("since 11:40 PM")
  - action items first
  - a prioritized list
  - deep links into the details
- **Nielsen Norman Group:**
  - Visibility of system status, so you always know *if* something is running and *why*.
  - Interrupt only for things that need action.
- **Stack choice (builder's call):** C# / .NET 9 WPF with the Fluent theme for a native Windows 11 tray app. The .NET SDK must be installed first (`winget install Microsoft.DotNet.SDK.9`).

## 6. Visual design research (round 2)

These are Apple's principles applied to Vigil.
- **Hierarchy, harmony, consistency.** These are Apple's Liquid Glass principles (WWDC25). Controls float as a light glass layer above the content, and corners are concentric (an inner radius equals the outer radius minus the padding). Hierarchy comes from spacing, size and grouping before color.
  Sources: [createwithswift](https://www.createwithswift.com/liquid-glass-redefining-design-through-hierarchy-harmony-and-consistency/) and [Apple Liquid Glass overview](https://developer.apple.com/documentation/technologyoverviews/liquid-glass).
- **Live Activities.** Show only the most essential content, with a leading icon or label and one trailing value. Update only when there's something new, and alert only when attention is truly needed. Activities have a defined start and end.
  Source: [9to5Mac on Apple's Live Activity guidelines](https://9to5mac.com/2022/09/26/iphone-14-pro-live-activities-guidelines/).
- **Progressive disclosure.** Show the essentials first and let people drill into details. Group notifications and minimize interruptions.
- **Menu bar utilities that people love** (iStat Menus and similar) do one job, keep the bar uncluttered, and put detail in a drop-down.
  Source: [Cult of Mac on iStat Menus](https://www.cultofmac.com/?p=2234).
- **Logo.** The CBS eye (William Golden, 1951) shows that one symmetric, high-contrast shape reads at any size and lasts for decades.
  Source: [Inkbot Design on the CBS logo](https://inkbotdesign.com/cbs-logo/).
  For Apple-style app icons: one bold glyph, a deep gradient, a soft top highlight, and a test at 16 px plus a one-color version.

How these show up in Vigil:
- The headline answers the user's real question ("Safe to close the lid.").
- Each session is described in one human sentence.
- Heat, battery and phone status stay hidden while they're fine.
- Each color has one meaning: blue = working, orange = needs you, green = done, red = danger.

### Short summaries

There are three layers:
1. **Headline** (≤20 words), written by `claude -p --model haiku`. It took about 8 s in a test on this machine and runs on the user's subscription.
2. **Fact chips** read deterministically from the transcript: files, tests, commits, deploys, errors.
3. **Timeline** of meaningful steps.

These are never dropped: questions to the user, errors and failed tests, installs, deletions, pushes, deploys, things Claude couldn't do, and usage limits.

Notes:
- The summarizer's own `claude -p` call must run with hooks disabled, so Vigil doesn't track its own summarizer as a session.
- Transcripts include `ai-title` records (session titles) and, when Remote Control is on, `claude.ai/code/session_…` URLs. Vigil can use those URLs to open a session for replying without the terminal.
